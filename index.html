MVC Architecture

Every project follows the same pattern — it keeps code organized, predictable, and easy to change. Here's how the data flows.

Model-View-Controller is just a way of splitting your code into three buckets. Models talk to the database. Controllers handle the logic. Views (the React frontend) handle what users see. A request always travels one direction, and the response flows back the same way.
View (React)
Request
Controller (logic)
Query
Model (SQL)
SQL
Database (SQLite)
View (React)
Response
Controller (logic)
Data
Model (SQL)
Rows
Database (SQLite)
Why MVC? Need to change how data is saved? Look in models/. Need to change what a button does? Look in client/src/pages/. Learn it once, use it everywhere.

Quick Start

Get a project running in four commands.

  1. 1

    Clone the repo

    Grab everything at once:

    # Clone the entire collection
git clone <repo-url> BuildItRight
  2. 2

    Pick a project

    They all share the same layout:

    cd BuildItRight/BasicCrudTODOApp
  3. 3

    Install dependencies

    Backend + frontend:

    npm install
npm install --prefix client   # skip if no client/ folder
  4. 4

    Start everything

    One command, both servers:

    npm run dev

Open http://localhost:5173 and you'll see it running.

Command What it does
npm run dev Starts backend + frontend together
npm run dev:api Starts only the backend
npm run dev:web Starts only the frontend
